Сайт открытый, и любая помощь приветствуется: исправленная опечатка полезна не меньше новой страницы. Здесь описано, какая помощь нужнее всего, как запустить сайт у себя, как устроен контент и что должно быть в pull request, чтобы его приняли.

<Aside type="tip" title="Коротко">
- Небольшая правка? Нажмите ссылку «Редактировать страницу» внизу любой страницы и откройте pull request прямо из браузера.
- Что-то крупнее — сначала прочитайте [руководство по контенту](https://github.com/butyavk/system-design/blob/main/CONTENT_GUIDE.md).
- Любое изменение вносится и в английскую, и в русскую страницу.
- Перед открытием pull request запустите `node scripts/check-mdx.mjs` для своих файлов и `npm run build`.
</Aside>

## Чем можно помочь

- **Исправить ошибки.** Фактические неточности, устаревшие утверждения, битые ссылки, неверные цифры в прикидках, опечатки. Если не знаете, как исправить, создайте [issue](https://github.com/butyavk/system-design/issues) с описанием проблемы и местом, где вы её нашли.
- **Улучшить страницу.** Более понятное объяснение, удачнее схема, недостающий компромисс, более точный блок «На собеседовании», лучший источник.
- **Добавить страницу.** Недостающая тема, разбор задачи или упражнение по ООП-дизайну. Сначала создайте issue, чтобы договориться о рамках и слаге (slug) и не делать одну работу дважды.
- **Улучшить перевод.** Сделать русский текст естественнее, выровнять терминологию по глоссарию или подтянуть русскую страницу до актуальной английской версии.

## Запуск сайта локально

Понадобятся [Node.js](https://nodejs.org/en/download) версии 22.12 или новее и Git.

<Steps>

1. Сделайте форк репозитория на GitHub и клонируйте его:

   ```bash
   git clone https://github.com/<your-username>/system-design.git
   cd system-design
   ```

2. Установите зависимости:

   ```bash
   npm install
   ```

3. Запустите сервер разработки. Он выведет локальный адрес (по умолчанию `http://localhost:4321/system-design/`) и будет перезагружать страницы при правках:

   ```bash
   npm run dev
   ```

4. Создайте ветку для изменений:

   ```bash
   git checkout -b fix/cap-theorem-typo
   ```

5. Закончив, один раз соберите весь сайт, чтобы убедиться, что ничего не сломалось. Результат попадает в `dist/`; `npm run preview` раздаёт его локально:

   ```bash
   npm run build
   ```

</Steps>

## Как устроен контент

```text
src/content/docs/
├── index.mdx                      главная страница на английском
├── start/introduction.mdx         английские страницы: <раздел>/<slug>.mdx
├── fundamentals/cap-theorem.mdx
├── ...
└── ru/
    ├── index.mdx                  главная страница на русском
    ├── start/introduction.mdx     русская пара: тот же раздел, то же имя файла
    └── ...
scripts/pages.json                 карта сайта: все разделы и слаги
scripts/check-mdx.mjs              самопроверка файлов контента
astro.config.mjs                   конфигурация сайта и группы бокового меню
CONTENT_GUIDE.md                   правила написания страниц
```

- **Английские** страницы лежат в `src/content/docs/<раздел>/<slug>.mdx`.
- **Русские** — в `src/content/docs/ru/<раздел>/<slug>.mdx`, с точно таким же разделом и именем файла.
- **Боковое меню** строится по папкам. Место страницы внутри раздела задаёт `sidebar.order` во frontmatter.
- **Новые страницы** нужно добавить в `scripts/pages.json`: внутренние ссылки разрешены только на перечисленные там страницы.
- **Внутренние ссылки** пишутся от корня, без локали и базового пути, и заканчиваются слешем: `/fundamentals/cap-theorem/`. Сборка сама добавит `/system-design` и `/ru`.
- **Схемы** — это блоки кода Mermaid; картинки не используются.
- **Интерактивные виджеты** из `src/components/` добавляет сопровождающий; если странице пригодился бы виджет, предложите его в issue.

Всё остальное описано в [руководстве по контенту](https://github.com/butyavk/system-design/blob/main/CONTENT_GUIDE.md): шаблоны страниц, frontmatter, стиль, англо-русский глоссарий, подводные камни MDX и требования к ссылкам. Прочитайте его, прежде чем писать или переписывать страницу.

## Правила написания и перевода вкратце

- **Своими словами.** Не вставляйте текст из оригинального Primer или с других сайтов. Берите из источников факты, объясняйте своими словами и давайте ссылки в разделе «Что почитать».
- **Актуально и точно.** Предпочитайте официальную документацию, научные статьи и инженерные блоги команд, которые построили систему. Проверяйте каждую внешнюю ссылку перед добавлением.
- **Оба языка в одном pull request.** Русская страница — не дословный перевод: та же структура, заголовки, схемы и код, но живым техническим русским языком, по глоссарию из руководства по контенту.
- **Пишете только на одном языке?** Всё равно открывайте pull request и укажите это в описании. Вторую половину кто-нибудь допишет до слияния.

## Проверка изменений

Скрипт самопроверки проверяет файлы контента без полной сборки: синтаксис MDX, полноту frontmatter, внутренние ссылки на несуществующие страницы и наличие языковой пары:

```bash
node scripts/check-mdx.mjs src/content/docs/fundamentals/cap-theorem.mdx src/content/docs/ru/fundamentals/cap-theorem.mdx
```

Каждый файл должен получить ✓. Исправьте все ✗, прежде чем открывать pull request, а в качестве финальной проверки запустите `npm run build`.

## Чек-лист для pull request

- [ ] Изменение внесено **и** в английскую, **и** в русскую страницу (или в описании сказано, какой половины не хватает).
- [ ] Frontmatter заполнен: `title`, `description` (120–160 символов), `sidebar.order`.
- [ ] Внутренние ссылки — от корня, заканчиваются на `/` и ведут на страницы из `scripts/pages.json`.
- [ ] Каждая новая внешняя ссылка открыта и работает.
- [ ] Цифры в прикидках пересчитаны, примеры кода запущены.
- [ ] `node scripts/check-mdx.mjs` проходит для всех изменённых файлов.
- [ ] `npm run build` завершается без ошибок.
- [ ] В описании сказано, что изменено и почему; для фактических исправлений указаны источники.

Если вы раньше не работали с pull request, руководство GitHub [о pull request из форка](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/proposing-changes-to-your-work-with-pull-requests/creating-a-pull-request-from-a-fork) пошагово объясняет процесс.
